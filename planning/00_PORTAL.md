# Planning portal

This is the top entry point for the canonical RDP planning layout.

The goal is to keep planning readable, portable, and usable by multiple agents
without losing the evidence trail.

## Read order

For repo-wide orientation:
1. `01_PROJECT_INDEX.md`
2. `05_CANONICAL_UPDATE_FORMAT.md`
3. `02_GLOBAL_OPEN_QUESTIONS.md`
4. `project_timeline/00_MASTER_TIMELINE.md`
5. `project_timeline/01_ACTIVE_COORDINATION_BOARD.md`
6. `project_timeline/02_DEPENDENCY_MAP.md`
7. `project_timeline/20_PROBLEM_THREADS_INDEX.md`

Then move into the relevant project home under `projects/`, or into
`planning_old/` if you are following historical links.

## Canonical status

This bundle is now the default repo-wide planning system.

Historical planning, migration notes, archive packs, completed packs, legacy
surfaces, and the old compatibility stub now live under:
- `planning_old/`

There are no separate top-level live planning exceptions now.

## Control-layer principles

- one global control layer
- one cross-project timeline layer
- one project home per real active project
- one small fixed status vocabulary
- reusable templates for future agent work
- support streams live under projects, not beside them
- old material should be preserved, but not allowed to compete with live truth
