# Open questions

## P1. What should count as the first canonical problem brief?
Likely:
- one short `5455` problem brief
- one current-state note
- one runbook
- one result log

## P2. How much of solve-proof belongs here versus as shared infrastructure?
The solve-proof tooling is shared, but the p13 real-ciphertext campaign should
own the interpretation and problem-thread planning that uses it.

## P3. How should the project timeline track general p13-learning versus real-ciphertext work?
Keep them separate:
- general learning under `benchmark_campaign_v1_1`
- real-ciphertext work here

## P4. What is the first useful status format?
Probably a compact one:
- problem id
- current best evidence
- current blocker
- next planned run/question

## P5. How should broader p13-readiness notes be used?
Use them as upstream context only.
Do not collapse them into fake direct `5455` history.

## P6. When should repeated raw no-WLI path lists disappear from thread notes?
When:
- exact upstream anchors are pinned in one dedicated note
- the upstream-link and upstream-reference-policy notes are enough for routing
- repeated copies stop adding clarity
