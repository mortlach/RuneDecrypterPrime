# No-WLI Deep Research Note Pack

Date: 2026-03-21
Status: Working note pack
Scope: `tools/benchmarks/periodic_sub_trans/no_wli`

## Purpose

This pack turns the two broad deep-research reports into a smaller decision set for the next phase of the no-WLI programme.

It is not another wide review of the whole problem.
It is the sharper follow-on pack that says:

- what is already settled enough to stop debating
- what is still uncertain
- what the next-phase decision documents should say

## Settled Position

These points are now settled enough to use as working assumptions:

- the project is promising, not fundamentally broken
- the current evidence shows real hard-family basin reach on `p9/c3/l1000`, with best observed match around `0.773`
- the main current blocker is Stage-3 basin quality, not general repo untidiness
- current scorers are useful but imperfect, not obviously the main driver of the hard-family collapse
- broad refactor is not the next main workstream
- the jump to `p13`, especially `l500`, is not incremental and likely needs both stronger priors and stronger search

## What This Pack Adds

The broad reports already answered the "is this worth pursuing and where is the main blocker?" question.
What was still missing was a smaller set of decision notes that can guide the next phase without drifting back into vague "wider research."

This pack provides exactly four of those notes:

1. `capability_ladder_no_wli_periodic_sub_trans_2026-03-21.md`
2. `method_families_next_capability_jump_2026-03-21.md`
3. `evidence_gaps_no_wli_periodic_sub_trans_2026-03-21.md`
4. `tactical_refactor_filter_solve_first_2026-03-21.md`

## Reading Order

Use the pack in this order:

1. Capability ladder:
   establishes what is proven now, what is plausibly next, and what is still speculative
2. Method families:
   compares the serious next candidate method families and ranks them for roadmap use
3. Evidence gaps:
   separates strong evidence from inference and defines what new evidence would actually change confidence
4. Tactical refactor filter:
   turns the solve-first stance into a practical approval rule for refactors
