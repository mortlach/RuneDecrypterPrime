# score_stop_shadow_v2 transparency hardening plan

## Purpose

Make the current offline stop science transparent enough that we can answer, with much less hand-waving:

* why a row dumped
* why a row did not dump
* which gate it failed on
* by how much it failed
* whether a seed is trust-led, rescue-led, persistent-but-untrusted, or just quiet
* whether `1111` is a genuine shape miss or just a threshold near-miss

This is an **offline benchmark-analysis change**, not a live solver change.

---

## Scope guard

### In scope now

* better offline gate transparency
* exact pass/fail margins
* full threshold matrix instead of first-hit-only summary
* per-seed digest
* per-family digest
* tests that prove no accidental behaviour drift

### Explicitly out of scope now

* changing live solver behaviour
* changing how rows are generated upstream
* changing family clustering
* changing replay scoring itself
* adding broad new rescue branches
* promoting anything to stop policy

---

## Main rule: no drift

The first implementation pass must preserve these current top-line outcomes on the locked nine-seed panel:

* `511` dumps
* `411` dumps
* `611` dumps
* `711` dumps
* `1011` dumps
* `811`, `911`, `1211` stay quiet
* `1111` still misses
* `would_stop` stays separate from `would_dump`

That means:

### Allowed in pass 1

* new fields
* new JSONL outputs
* new markdown summaries
* richer diagnostics
* full threshold reporting
* clearer per-seed and per-family summaries

### Not allowed in pass 1

* any change that alters current `shadow_high_score_rule_id`
* any change that alters current `shadow_high_score_would_dump`
* any change that alters current `would_dump`
* any change that implicitly turns on stop logic
* any silent change to row ordering or seed selection

If any of those change, that is not “transparency hardening”. That becomes a separate deliberate science change.

---

# Why this is the right next step

The current code already tells us useful things, but too opaquely.

The main bottleneck is in `tools/benchmarks/periodic_sub_trans/no_wli/analysis/score_stop_shadow_v2/extract_score_stop_shadow_v2.py`:

* `_annotate_shadow_rows(...)` decides the dump rule by taking the **first passing** threshold combination and then breaking out early (`lines 1127-1193`)
* `_annotate_stability(...)` is the stop-side family-boundary logic (`lines 1196-1254`)
* `analyze_artifact(...)` currently skips stability when `SCORE_PANEL_DISABLE_FAMILY_STOP = True` (`lines 168 and 1452-1454`)
* `build_threshold_sweep_summary(...)` only summarises the final chosen rule per run, not the full pass/fail picture (`lines 1459-1490`)

So right now the harness is usable, but it does not expose the real structure of the near-misses cleanly enough.

# Exact implementation plan

## Step 1 — factor gate evaluation into one explicit helper

### Add new helper

Add a helper with a clear name, something like:

`_evaluate_dump_gate(...)`

Inputs:

* `row`
* `rows_in_pool`
* threshold values:

  * `trust_floor`
  * `xent_ceiling`
  * `rival_margin_floor`
  * `family_support_floor`

Outputs:

* `pass: bool`
* full gate evaluation dict

That dict must include:

* raw values
* threshold values
* pass/fail booleans
* signed margins
* blocker list
* rule id string

### Why

Right now the logic is partly split between `_qualifies_dump(...)`, `_diagnostic_dump_metrics(...)`, and the early-break loop in `_annotate_shadow_rows(...)`.

That makes it harder to prove exhaustiveness and harder to write a threshold matrix cleanly.

### No-drift requirement

The final pass/fail decision for the existing first-hit path must remain identical to today.

---

## Step 2 — add signed margins for every gate

For every row, emit these new fields.

### Trust / xent / support / rival margins

* `shadow_margin_trust`
* `shadow_margin_xent`
* `shadow_margin_family_support`
* `shadow_margin_rival_margin`

Interpretation:

* positive means passed by that amount
* negative means failed by that amount
* zero means exactly on the line

Suggested meaning:

* `shadow_margin_trust = actual_trust - trust_floor`
* `shadow_margin_xent = xent_ceiling - actual_xent`
* `shadow_margin_family_support = support_count - support_floor`
* `shadow_margin_rival_margin = actual_rival_margin - rival_margin_floor`

### Existing blocker fields must stay

Do not remove:

* `shadow_diag_blockers`
* `shadow_diag_trust_pass`
* `shadow_diag_xent_pass`
* `shadow_diag_family_support_pass`

Just add the margins alongside them.

### Why

This is the single most important transparency improvement.
It turns “failed trust” into “failed trust by 0.17”, which is much more scientifically useful.

## Step 4 — keep current first-hit behaviour, but expose nearest miss

For rows that do not dump, add:

* `shadow_nearest_pass_rule_id`
* `shadow_nearest_pass_blocker`
* `shadow_nearest_pass_margin`

This should mean:

* among all tested rules, find the one that was closest to passing
* identify the blocker that most directly prevented pass

Example:
if trust is the only failed gate and it misses by 0.04, that should be the nearest pass blocker.

### Important

Do not turn this into fuzzy multi-gate ranking magic.
Keep it simple and explicit:

* prefer rules with the fewest failed gates
* then the smallest worst negative margin
* then stable deterministic tie-break on rule id

### Why

This gives a clean answer to:
“is `1111` structurally outside, or is it one gate away?”

## 2) add tiny signed-margin helpers

Do not duplicate sign logic in six places.

```python
def _margin_at_least(actual: Any, floor: float) -> float:
    value = _safe_float(actual)
    if not _is_finite(value):
        return float('nan')
    return float(value) - float(floor)


def _margin_at_most(actual: Any, ceiling: float) -> float:
    value = _safe_float(actual)
    if not _is_finite(value):
        return float('nan')
    return float(ceiling) - float(value)
```

For integer-style floors:

```python
def _margin_count_at_least(actual: Any, floor: int) -> int:
    return int(_safe_int(actual, 0) - int(floor))
```

### Why

It keeps sign conventions consistent:

* positive = passed
* negative = failed

### Test to add

`test_margin_helpers_return_positive_zero_and_negative_values()`

```python
) -> dict[str, Any]:
```

### Keep the ranking simple

Use a stable ranking:

1. fewest failed gates
2. smallest worst negative margin
3. smallest total negative deficit
4. deterministic tie-break on `rule_id`

### To make that work

Each threshold row should include:

* `failed_gate_count`
* `worst_negative_margin`
* `total_negative_deficit`
* `primary_blocker`

For example, for a trust rule:

* if trust and support fail, `failed_gate_count = 2`
* `worst_negative_margin = min(trust_margin, support_margin)`
* `total_negative_deficit = abs(sum(min(0, each_margin)))`
* `primary_blocker = 'trust_below_floor'` if trust is the worst failed margin

### Important simplification

Do not try to compare trust margins and support margins in a philosophically perfect way.
This is a practical diagnostic, not a theorem.

```python
def _annotate_shadow_rows(rows: list[dict[str, Any]]) -> list[dict[str, Any]]:
    grouped = _group_rows_by_pool(rows)
    out_rows = [dict(row) for row in rows]
    by_artifact = ...
    for idx, row in enumerate(out_rows):
        rows_in_pool = ...
        artifact_rows = ...

        base_metrics = _diagnostic_dump_metrics(...)
        base_metrics.update(_late_family_persistence_metrics(...))
        base_metrics.update(_late_family_continuation_metrics(...))

        threshold_rows = _build_threshold_matrix_rows_for_row(
            row,
            rows_in_pool,
            artifact_rows,
        )

        first_hit_rule_id = ''
        for threshold_row in threshold_rows:
            if str(threshold_row.get('rule_family', '')) == 'continuation_archive':
                continue
            if int(threshold_row.get('pass', 0) or 0) == 1:
                first_hit_rule_id = str(threshold_row.get('rule_id', ''))
                break

        if not first_hit_rule_id and str(ANALYSIS_MODE) == 'family_panel_v1':
            for threshold_row in threshold_rows:
                if str(threshold_row.get('rule_family', '')) != 'continuation_archive':
                    continue
                if int(threshold_row.get('pass', 0) or 0) == 1:
                    first_hit_rule_id = str(threshold_row.get('rule_id', ''))
                    break

        for threshold_row in threshold_rows:
            threshold_row['is_first_firing_rule'] = int(
                str(threshold_row.get('rule_id', '')) == str(first_hit_rule_id)
                and bool(first_hit_rule_id)
            )

        nearest = _pick_nearest_pass_rule(threshold_rows)

        out_rows[idx] = dict(
            row,
            **base_metrics,
            shadow_high_score_rule_id=str(first_hit_rule_id),
            shadow_high_score_would_dump=int(bool(first_hit_rule_id)),
            shadow_high_score_would_stop=0,
            shadow_stability_rule_id='',
            shadow_stability_would_stop=0,

            shadow_nearest_pass_rule_id=str(nearest.get('rule_id', '')),
            shadow_nearest_pass_blocker=str(nearest.get('primary_blocker', '')),
            shadow_nearest_pass_margin=_safe_float(nearest.get('worst_negative_margin', float('nan'))),

            shadow_threshold_rule_count=int(len(threshold_rows)),
        )

        out_rows[idx]['_shadow_threshold_matrix_rows'] = threshold_rows
    return out_rows
```

### Important note

That private field with a leading underscore is okay **inside memory**.
Do not write it to `row_scores.jsonl`.

So before writing row JSON, strip any keys starting with `_shadow_`.

That can be done in a tiny helper.

```python
def _strip_private_analysis_fields(row: Mapping[str, Any]) -> dict[str, Any]:
```

# one more useful guard

Because this is the sort of analysis code that drifts quietly, add one tiny regression helper in the test file:

```python
def _canonical_run_verdicts(rows: Sequence[Mapping[str, Any]]) -> list[tuple[str, int, int, str]]:
    out = []
    for row in rows:
        row_d = dict(row)
        out.append(
            (
                str(row_d.get('artifact_path', '')),
                int(row_d.get('would_dump', 0) or 0),
                int(row_d.get('would_stop', 0) or 0),
                str(row_d.get('shadow_rule_id', '')),
            )
        )
    return sorted(out)
```

Then use that in the no-drift integration tests.
That makes accidental output changes very obvious.
