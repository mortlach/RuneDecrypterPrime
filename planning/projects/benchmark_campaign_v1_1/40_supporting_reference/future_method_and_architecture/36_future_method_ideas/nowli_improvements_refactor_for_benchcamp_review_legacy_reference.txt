Critical disagreements / gaps
1) Public campaign contract conflict (no-WLI + WLI expansion in same track).
Why this matters:
- Your proposal treats no-WLI-first campaign unification as immediate; current v1.1 public contract explicitly excludes that.
Evidence:
- tools/benchmarks/community/schemas/manifest_schema_v1_1.json:37-52 (period 7..13, order enum only col_then_sub/sub_then_col)
- tools/benchmarks/community/schemas/result_schema_v1_1.json:150-160 (device cpu, backend numpy)
- tools/benchmarks/periodic_sub_trans/no_wli/README.md:17-18 (no_wli is internal scope)
- planning/drafts/campaign_spec_v1_1.md:21-27
- planning/drafts/community_benchmark_unified_plan_v1_1.md:47

Better alternative within RDP goals:
- Keep public v1.1 unchanged.
- Add a separate internal campaign schema/version for no-WLI/wider flavor space.
- Promote into public schema only after gates close.

2) "One StageEngine" is not near-term compatible with current architecture boundaries.
Why this matters:
- Core engine is a Stage-2 solver orchestrator, not a benchmark stage/pool engine.
- Flavor runners contain materially different stage search shapes today.
Evidence:
- src/rune_decrypter_prime/core/engine/engine.py:3, 21, 152-157
- tools/benchmarks/periodic_sub_trans/col_then_sub/runner.py:4-19
- tools/benchmarks/periodic_sub_trans/sub_then_col/runner.py:6-12
- tools/benchmarks/periodic_sub_trans/no_wli/runner.py:5-12
- planning/drafts/benchmarks_periodic_sub_trans_refactor_plan.md:12-14 (explicitly structural, not algorithm rewrite)

Better alternative:
- Implement StageSpec/PolicySpec in tools/benchmarks layer first (not in core engine).
- Extract shared orchestration into periodic_sub_trans/common (the exact direction already tracked in W2).

3) "First-class ScorerResult object used pervasively across RDP" is too invasive right now.
Why this matters:
- Scorer contract and solver runtime currently depend on scalar/array returns and tuple raw APIs.
Evidence:
- src/rune_decrypter_prime/scoring/base_scorer.py:75-89, 98-116
- src/rune_decrypter_prime/core/problem/runtime.py:563-572, 582-590
- src/rune_decrypter_prime/core/engine/engine.py:129-135 (scorer meta is lightweight telemetry map)

Better alternative:
- Add an optional structured scorer sidecar in telemetry/output first.
- Keep numeric score interfaces stable for solver loops in this refactor.
- Migrate callsites incrementally only after compatibility wrappers exist.

4) The proposal assumes campaign dispatch across all target flavors, but current dispatch is intentionally limited.
Evidence:
- tools/benchmarks/community/_run_single_job.py:41-51 (only col_then_sub/sub_then_col)
- tools/benchmarks/periodic_sub_trans/no_wli/runner.py:66 (currently pinned to COL_THEN_SUB)
- tools/benchmarks/periodic_sub_trans/common/core_enums.py:6-8 (BenchmarkOrder has only two values)
- Search result: no `configure_campaign_run` in tools/benchmarks/periodic_sub_trans/no_wli/runner.py (only present in col_then_sub/sub_then_col runners).

Better alternative:
- If no_wli enters campaign dispatch, add explicit flavor routing and a no_wli runner entrypoint contract first.
- Do not overload existing order enum.

Concrete revisions I recommend for your proposal text
1) Add an explicit two-track contract:
- Track A (public v1.1): unchanged schema/compliance.
- Track B (internal no_wli/wli extension): new schema version + explicit flavor field.

2) Scope the StageEngine refactor to benchmark layer first:
- StageSpec/AdaptivePolicySpec in tools/benchmarks/periodic_sub_trans/common.
- Core engine unchanged in this wave.

3) Reframe ScorerResult as phased:
- Phase 1: structured telemetry/output sidecar.
- Phase 2: optional API exposure.
- Phase 3: pervasive runtime adoption (only after compatibility gates).

4) Add preconditions before acceptance criteria:
- scorer_schedule plumbing complete,
- no_wli campaign dispatch entrypoint added (if needed),
- S2 crash gate closed or fallback policy locked and tested.

5) Keep hardcoded run-file controls for operator workflows (repo rule-aligned), and avoid introducing CLI-arg driven tuning in this wave.
Evidence:
- tools/benchmarks/periodic_sub_trans/no_wli/README.md:22

Final judgment
- Keep the proposal direction.
- Convert it into a phased architecture RFC with strict compatibility gates.
- Do not approve as a single-wave implementation plan yet; approve as a vNext roadmap after the above scope corrections.
