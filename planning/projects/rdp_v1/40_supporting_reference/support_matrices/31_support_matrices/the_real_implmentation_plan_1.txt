WS5 — first-class campaign surface

This is the biggest and riskiest workstream.

Current repo reality
You effectively have two campaign surfaces already:

an outer community config/schema/bundle/sharding surface

an inner stage-engine/stage-spec/policy-engine surface
plus a large no-WLI orchestration mass around them

The campaign spec already recognises exactly this and says it should be treated as extraction and formalisation rather than zero-to-one invention.

Goal
Create one governed campaign surface that preserves the real LP attack workflows and then gradually moves architecture toward first-class ownership instead of leaving it in tools/.

Repo hotspots

Effort
Very large.

Why
This is by far the biggest concentration: about 226 files / ~60k lines in the main impact zone, with the no-WLI runner area alone being huge.

Key warning
Do not start this by moving files into campaigns/.
Start it by:

freezing contract tests,

introducing façade/adapter surfaces,

only then regrouping ownership.

That matches the handbook and refactor plan: parity before tidiness, and no big structural moves first.

The landing order I would actually use

I would make the implementation plan say this, plainly:

Phase A — control pack and mapping

Do this first.

create CURRENT_PHASE, ACTIVE_TODO, ADRs, workflow pack

write the current-code mapping note

write the workstream touchpoint tables

Phase B — guardrails and support proof scaffolding

Before any major refactor:

freeze matrix wording

map matrix cells to tests

add missing guardrails where behaviour is important but poorly protected

Phase C — output/privacy and report contract stabilisation

Do these before big campaign extraction:

one output/privacy owner

ScorerReport contract tightening

SolverReport minimum contract landing

formal rescoring retained-state contract

Phase D — RunSpec/front-door convergence

introduce real RunSpec

adapt tutorials, API use, and campaign-generated runs to it

keep boundary forgiving, core strict

Phase E — campaign formalisation without tree churn

create the first governed campaign façade

widen StageSpec / wrap AdaptivePolicySpec

keep serious LP stage behaviour

do not yet do broad repo moves

Phase F — campaign ownership lift

move stable campaign architecture toward first-class ownership

reduce runner-local duplication

shrink tools/ to genuinely auxiliary code

Phase G — LP/assets alignment and release-proof pass

finalise asset governance

proof runs

docs/test alignment

release checklist

That order is almost exactly what the handbook and refactor plan already imply; it just needs to be written in repo-aware form.

Instead:

turn the handbook into a real workflow pack,
