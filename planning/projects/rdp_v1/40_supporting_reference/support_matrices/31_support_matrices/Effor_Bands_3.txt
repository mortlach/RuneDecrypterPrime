Effort bands

These are rough single-maintainer active-work estimates, excluding waiting time, review delay, and unrelated opportunistic bug work.

S: 1–2 days

M: 3–5 days

L: 1–2 weeks

XL: 2–4 weeks

XXL: 1–2 months

From the uploaded source tree, the real blast radius looks roughly like this:

run/front-door area: about 46 files

output/privacy focused area: about 13 files

LP/assets area: about 49 files

campaign/no-WLI/test-heavy area: well over 200 overlapping files in the likely impact zone

So the big uncertainty is not the simple typed core pieces. It is still the campaign and no-WLI plumbing.

Overall scale

My honest estimate is:

Planning/control pack + mapping: about 2–3 weeks

Contract hardening before campaign lift: about 4–7 weeks

Campaign façade + ownership lift: about 8–14 weeks

Proof pass + release alignment: about 2–4 weeks

So as one careful maintainer, this is roughly 4–6 months of stop-start convergence work. With parallel help and tight review discipline, shorter. With broad reshaping or repeated re-arguing, longer.

Suggested first ticket stack

If you want the smoothest start, I would not open ten tickets at once. I would start with these seven, in this order:

P0.1 planning/control pack

P0.3 current-code mapping note

P1.1 matrix wording + cell meanings

P1.2 support-to-test mapping

P2.1 output/privacy owner inventory

P2.3 ScorerReport minimum contract

P3.1 front-door surface inventory

That gives you the execution spine before the harder architectural moves.

What should stay out of scope for now

Do not do these early:

broad tree moves

rename-driven cleanup

campaign package relocation before façade/gates exist

speculative new feature families

over-designed long-term campaign analysis layer

“temporary” second front doors that are likely to stick

Those are exactly the failure modes the current docs warn against.

My blunt prioritisation

If you ask which three things matter most for a smooth refactor, I would say:

first: make the handbook operational with real planning files
second: write the current-code mapping note
third: stabilise output/report/reconstruction contracts before touching campaign ownership

That sequence best matches the owner docs and best protects the serious no-WLI / LP attack behaviour while you converge the architecture
