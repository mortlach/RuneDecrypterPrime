# Project definition and agent rules

Status: active

## What counts as a project home

A project home should be the first reading surface for a coherent stream of
work.

A project home should answer:
- what this project is
- what is active now
- what should be read first
- what is still open
- where support/reference/history sits

## What does not count as a project home

Do not create a separate project home just because:
- a folder exists
- a few notes share a topic
- an old cluster was preserved
- a one-off experiment had a name

Those usually belong as:
- supporting reference
- future-method ideas
- archive/history
- one problem thread inside a larger project

## Live truth versus reference versus archive

### Live truth
Use for:
- current state
- workstream index
- active runbook
- remaining work
- current decisions/rules
- current result/status notes

### Supporting reference
Use for:
- useful secondary notes
- support matrices
- method references
- future-architecture ideas
- legacy clusters with still-relevant lessons

### Archive/history
Use for:
- preserved old packs
- source bundles
- handoff notes
- forensic/history material
- material kept mainly for provenance

## Upstream versus downstream rule

If one project is a proving ground or method-development parent, do not silently
re-home it inside a downstream thread pack.

Example:
- `no_wli` stays upstream
- `p13_real_ciphertext_campaign` stays downstream and may reference it

## Agent rule

When updating planning:
- prefer improving the existing project home
- do not create new homes casually
- do not let rescued legacy files become front-door truth
- add small, explicit notes rather than hidden silent drift
