# Agent update and logging rules v1

Status: active
Work status: done
Project: project_workflow

## Core rule

Agents should prefer:
- small explicit updates
over:
- large silent structural drift

## When adding a new note

Ask:
1. is this live truth?
2. is this supporting reference?
3. is this archive/history?
4. is this really a separate project, or just a subtopic inside one?

## Logging rule

When meaningful work happens, prefer adding:
- a short result note
- a status ledger update
- a remaining-work adjustment

rather than only editing long prose files.

## Legacy-material rule

Only rescue legacy material when it contributes:
- a real guardrail
- a real design lesson
- a useful historical review
- a clearly relevant method reference

Do not rescue things just because they exist.

## Update-order rule

For active projects, update in this order where possible:
1. `00_CURRENT_STATE.md`
2. `04_ACTIVE_RUNBOOK.md`
3. `05_REMAINING_WORK.md`
4. result/status notes
5. secondary reference layers

## Thread rule

For downstream thread packs:
- keep thread material front and centre
- keep upstream method homes external
- do not re-home upstream work casually
