Plan goal
- Implement LP typed domain layer as an adapter over existing LP foundation.
- Keep current LP APIs stable while introducing canonical typed APIs.

Guiding constraints
- No rewrite of `lp_transcript.py` core parsing in phase 1.
- No CLI expansion for helper scripts.
- No absolute path leakage in persisted outputs/logs.
- Typed core only; UI token parsing remains in `lp_ui_parse.py`.

Risk register
1) Parallel surface drift
- Risk: duplicate APIs diverge.
- Mitigation: one canonical typed surface + shims only.

2) Enum persistence drift
- Risk: unstable persisted names.
- Mitigation: explicit string enum values.

3) Hidden behavior changes in transcript parsing
- Risk: parity regressions.
- Mitigation: no parser rewrites in LP1/LP2; parity tests mandatory.

4) Over-coupling into solver core
- Risk: LP concerns leak into core.
- Mitigation: keep LP domain in `data/liber_primus`; solver receives only adapter payloads.

Definition of done (for this plan)
- Typed LP domain layer exists in repo and is primary documented surface.
- Existing LP usage paths remain functional (compatibility preserved).
- LP adapter produces deterministic solver payloads for typed locators/partitions/routes.
- Solved-page and section examples are runnable and tested.
