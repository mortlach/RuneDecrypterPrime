## Coordinated Discussion Spec After Research and Early Implementation Results

Status: discussion draft
Purpose: align dev, research, and active data work before the next scorer tranche
Scope: no-WLI n-gram phrase-coherence scoring after word/span-Hamming
Production status: no production scoring change approved

## 1. One-sentence direction

We should integrate the deep-research scoring architecture into the active RDP no-WLI plan, while treating the current order-2 evidence only as the first simple slice we happened to run, not as proof that order-2 is the final scorer direction.

The coordinated direction is:

```text
research-led architecture
implementation-tested machinery
evidence-gated profile promotion
no production scoring change yet
```

## 2. What this spec is trying to fix

There is a risk of two bad interpretations.

Bad interpretation 1:

```text
Order-2 produced the first visible signal, so order-2 is the scorer direction.
```

That is wrong. Order-2 was run first because it was simpler and cheaper. It has not been fairly compared with full order-3, order-4, or order-5 evidence.

Bad interpretation 2:

```text
Research says 3/4-grams should be central, so ignore the order-2 evidence.
```

That is also wrong. The order-2 signal is still useful. It tells us the matcher, assets, thresholds, and candidate strata are producing real evidence somewhere. It should be inspected, but not promoted.

Correct interpretation:

```text
Order-2 is an early instrumentation and evidence lead.
Order-3 is the first serious phrase-coherence test.
Order-4 is the expected stronger confirmation test.
Order-5 remains optional and probably diagnostic.
```

But infrastructure readiness is not the same as scorer readiness.

### 3.2 Scientific readiness

The current evidence is not yet sufficient for a production scorer.

Current evidence should be treated as:

```text
candidate-comparability evidence
implementation/parity evidence
early signal discovery evidence
not controlled damage-ladder proof
not full raw/provenance-grade proof
not production ranking proof
```

### 3.3 Key empirical observations so far

Observed so far:

* Exact joined n-gram scanning was effectively null.
* This supports moving away from exact joined phrase scanning.
* Word-structured Hamming is the right semantic direction.
* The first non-zero useful signal so far was normal/order-2/P1-P2 style evidence.
* P1/P2 were almost redundant in the balanced slice.
* Raw P2 separated selected strata, but it was not safe as a standalone pairwise scorer.
* Direct additive combination with the current score was unsafe.
* Panel-rescue known-better candidates had zero P2 hits in the tested slice.
* Order-3 full raw assets are still not fully interpreted.
* Order-4 has not yet been run in this tranche.

Therefore:

```text
Order-2 is active so far.
Order-2 is not promoted.
Order-3 and order-4 remain the expected better phrase-coherence evidence.
```

## 4. Research-led architecture to preserve

The deep-research outcome should now govern the scorer direction.

The v1 semantic model remains:

```text
exact word-structured phrase Hamming
```

The scorer should ask:

```text
Do local word-like spans line up into plausible ordered phrase evidence?
```

It should not merely ask:

```text
How many n-gram hits did we get?
```

### 4.1 Core rules

Preserve these rules:

* phrase evidence is positive support only;
* absence of phrase hits is not a penalty;
* FWD and REV must not be silently mixed;
* normal and strict cuts must remain separate;
* all eligible hits for a declared profile are counted exactly;
* no hit caps;
* no top-k;
* no silent Python fallback;
* no silent profile narrowing;
* no direct additive score fusion;
* no production scorer change yet.

### 4.2 Phrase identity

Canonical phrase identity is structured:

```text
direction
dictionary_cut
ngram_order
canonical word_token_ids
```

Flattened token IDs may be used for scanning, but not as the only identity.

This matters because two phrases can share a flattened token sequence while having different word boundaries.

### 4.3 Why word-structured Hamming

The scorer compares each phrase word by word.

For a phrase with word lengths:

```text
L1, L2, L3, ...
```

and a candidate start offset `s`, compare:

```text
candidate[s : s+L1]                       against word 1
candidate[s+L1 : s+L1+L2]                 against word 2
candidate[s+L1+L2 : s+L1+L2+L3]           against word 3
...
```

The scorer records:

```text
word_hds
total_phrase_hd
max_word_hd
phrase_token_length
normalised_phrase_hd
exact_flag
```

This keeps phrase evidence interpretable.

## 5. Handling variable n-gram order and phrase length

A key design point is that “n-gram order” and “phrase token length” are not the same thing.

### 5.1 N-gram order

Order means number of words:

```text
order 2 = two-word phrase
order 3 = three-word phrase
order 4 = four-word phrase
order 5 = five-word phrase
```

Expected roles:

```text
order 2:
  easiest to hit
  most likely to produce accidental support
  useful for instrumentation and coverage checks
  risky as score-bearing evidence

order 3:
  likely best centre of gravity
  stronger phrase-coherence evidence
  should be the first serious scorer test once full assets are ready

order 4:
  stronger confirmation
  sparser
  likely useful for high-confidence support or bounded override later

order 5:
  very sparse
  useful when present
  diagnostic unless surprisingly active
```

### 5.2 Phrase token length

A two-word phrase can be short or long.

Examples:

```text
order 2, short token length:
  short word + short word

order 2, long token length:
  long word + long word

order 3, short token length:
  three short words

order 3, long token length:
  three longer words
```

Therefore the scorer should never judge phrase strength by order alone.

Every profile should include:

```text
order set
cut set
minimum phrase token length
maximum total HD
maximum word HD
score-bearing or diagnostic role
```

### 5.3 Why minimum token length matters

Short phrases are easier to hit by chance.

So even inside the same order, we need token-length gates.

For example:

```text
order 2, token length 5, HD <= 2
```

is much weaker than:

```text
order 2, token length 12, HD <= 1
```

The proposed scorer therefore handles variable phrase length through explicit profile thresholds, not one global rule.

### 5.4 Why max-word-HD matters

A total phrase HD cap is not enough.

For example, a phrase could have total HD 2, but both mismatches could sit in the same short word. That may be less convincing than two mild word-level mismatches spread across the phrase.

So profiles should use both:

```text
max_total_phrase_hd
max_word_hd
```

This is the main reason to keep the scorer word-structured.

### 5.5 Normalised HD

The scorer should record:

```text
normalised_phrase_hd = total_phrase_hd / phrase_token_length
```

But normalised HD should be diagnostic or tie-break metadata, not the primary v1 gate.

Reason:

A low average mismatch rate can hide one badly damaged word.

## 6. Counts and log-counts

The phrase assets include count and log-count metadata.

These should be preserved in hit records and summaries.

For v1 discussion:

```text
count/log_count = diagnostic only
```

They should not be score-bearing yet.

Reason:

* high-frequency phrases can be generic;
* raw frequency can reward common phrase-like noise;
* count weighting requires stable full assets;
* count weighting also requires smoothing/back-off choices;
* sample-mode assets can make count interpretation unreliable.

Possible later use:

```text
weak tie-break only
full-asset mode only
clipped weighting only
after hard-pair and null evidence
```

No count/log-count weighting should enter the next non-production scorer slice.

---

## 7. Cluster-based evidence

Raw hit count must not be the score.

Earlier feature work showed that high-volume local/repeated structure can create many apparent rescues while causing too many breaks.

Therefore the next scorer should use cluster support.

### 7.1 v1 cluster definition

For discussion, use this simple deterministic definition:

```text
A phrase coherence cluster is a connected component of score-bearing or diagnostic phrase-hit intervals whose flattened token intervals overlap or touch.
```

For a hit with start `s` and phrase token length `L`, define:

```text
interval = [s, s + L)
```

Two hits belong to the same cluster if:

```text
next.start <= current_cluster_end
```

A new cluster begins only if:

```text
next.start > current_cluster_end
```

This is strict enough to collapse local repeated-hit bursts, but does not introduce a new gap parameter.

### 7.2 Cluster rule for scoring

For any profile family:

```text
raw_hit_count = diagnostic
cluster_count = possible support unit
```

Within one cluster:

```text
each profile family contributes at most one support unit
```

This prevents one local noisy region from generating many score-bearing units.

### 7.3 Cluster diagnostics

Every diagnostic pack should include:

```text
raw_hit_count
cluster_count
exact_hit_count
exact_cluster_count
unique_phrase_id_count
unique_start_count
hit_to_cluster_ratio
top_phrase_share
best_hit_signature
```

A profile that has high raw hits but low cluster diversity should be treated cautiously.

## 8. Exact hits

Exact hits should be visible, but should not become a separate profile ladder yet.

Recommended fields:

```text

exact_hit_count_global
exact_cluster_count_global
best_exact_hit_signature
```

Exact hits are useful audit/control evidence.

They should not cause profile explosion in the next discussion slice.

## 14. Matched nulls

Random token nulls are not enough because the scorer runs after word/span-Hamming.

The nulls should preserve local word-like evidence while breaking phrase coherence.

First matched nulls to discuss:

```text
offset_permute_null:
  preserve real local support spans
  permute their offsets or order
  destroy true adjacency and phrase order

window_collage_null:
  stitch local support windows from comparable candidates
  preserve local word-like evidence
  destroy candidate-specific phrase continuity

periodic_decoy_null:
  preserve repeated local structure pressure
  stress-test inflation from repeated phrase-like fragments
```

These should be deterministic, seeded through run manifests, and report-only at first.

Null diagnostics:

```text
real_vs_null_cluster_lift
real_vs_null_exact_cluster_lift
raw_hit_inflation
hit_to_cluster_ratio
top_phrase_share
support tuple flips
```

```text

Were candidate spans too damaged for contiguous phrase Hamming?
```

Outputs:

```text

chunk id

```

Keep this audit small and explanatory.

## 16. Promotion gates

No profile is promoted because it has hits.

A profile can only move forward if it passes evidence gates.

Required gates:

```text
exact all-hit accounting passes
deterministic rerun passes
normal/strict separation preserved
FWD/REV separation preserved
no silent fallback
positive net rescues
low or zero breaks
support adds evidence beyond current word/span score
support survives matched null checks
no concentration failure
no domination by one phrase or one local region
```

Concentration checks:

```text
top_phrase_share
hit_to_cluster_ratio
single-cluster domination
unique_phrase_id_count
unique_start_count
```

Order-2 has an extra burden:

```text
because order-2 is shorter and easier to inflate,
it must pass stricter concentration/null checks before it gets any scoring role.
```

## 17. Offline decision modes

Any decision logic remains offline.

Modes:

```text
report_only:
  compute phrase evidence
  do not change ranking

tie_break:
  phrase tuple may resolve predeclared close or tied baseline cases only

bounded_override:
  phrase tuple may override only under strict, predeclared, high-confidence conditions

direct_additive:
  forbidden for this tranche
```

Current production ranking remains unchanged.
