## Purpose

Build a **true report-only coherence scorer** using the filtered n-gram lists that have now been created from the current strict and normal word lists and encoded in FWD and REV forms.

The goal is to test whether ordered phrase evidence improves no-WLI hard-pair ranking beyond:

```text
current scorer
span-Hamming Panel A / S5
normal length 7 HD2 exact_count_norm
simple coherence proxy v1
```

This is still **report-only**. Do not change production scorer weights, defaults, or ranking policy.

## Core idea

Span-Hamming tells us:

```text
Does this candidate contain local word-like material?
```

The n-gram coherence scorer should tell us:

```text
Does this candidate contain ordered phrase-like material?
```

The previous coherence proxy showed that order/coherence helps suppress span-Hamming breaks. Now we want to replace or strengthen that proxy using real filtered n-gram evidence.

## Non-negotiable constraints

```text
FWD and REV must never be combined into one calibration or scoring surface.
First hard-pair report should be FWD only.
Use NOSE/no-WLI candidate tokens.
Do not assume word boundaries in candidate text.
Do not change production scoring.
Keep all score definitions explicit and auditable.
Use strict and normal n-gram lists separately.
Record exactly which filtered n-gram list versions were used.
```

## Available input assumption

Assume we now have filtered n-gram assets:

output/tools/benchmarks/periodic_sub_trans/no_wli/analysis/phaseB_filtered_ngram_index_v1/20260514T044954Z__phaseB_filtered_ngram_index_v1

```text
strict 2-grams, 3-grams, 4-grams, maybe 5-grams
normal 2-grams, 3-grams, 4-grams, maybe 5-grams
FWD-encoded phrase token sequences
REV-encoded phrase token sequences
frequency/count/log-count metadata if available
```

If 5-grams are not yet built, v1 should run with 2–4 and leave 5-gram fields as absent/disabled, not guessed.

# Phase 2 — Build a no-WLI exact phrase scanner

## Goal

Implement the first true n-gram coherence extractor.

For v1, use exact encoded phrase scanning:

```text
candidate rune stream
scan all offsets
look for exact encoded n-gram phrase token sequences
```

No word boundaries are assumed.

## Important limitation

This mode can match phrase token sequences across accidental boundaries. That is acceptable for v1 **only if** all results are evaluated against hard pairs and null/bad candidates. It must not be interpreted as true word-segmented phrase evidence.

## Script / module

Prefer reusable core code plus a report runner:

```text
filtered_ngram_phrase_scanner_v1.py
run_phaseB_filtered_ngram_hard_pair_report_v1.py
```

## Candidate input

Use the same resolved hard-pair candidate token streams already used by the hard-pair road tests.

Expected input set:

```text
2594 historical hard pairs
604 resolved candidate token streams
FWD token streams
```

## Scanning features

For each candidate chunk and each n-gram table:

```text
dictionary_cut: strict, normal
ngram_order: 2, 3, 4, optional 5
direction: fwd
```

compute:

```text
hit_count
unique_hit_count
weighted_hit_sum
log_weighted_hit_sum
max_log_weight
top_k_log_weight_sum
longest_encoded_phrase_hit
total_hit_token_coverage
hit_density_per_500
mean_hit_length_tokens
max_hit_length_tokens
top_hit_phrases
```

Also compute overlap-aware features:

```text
nonoverlap_hit_count
nonoverlap_weighted_hit_sum
nonoverlap_token_coverage
```

This matters because common phrases may overlap heavily.

## Weighting modes

For each table, compute at least:

```text
unweighted
log_count_weighted
rank_weighted if available
binary_presence
```

If raw frequency/count metadata is not available, use unweighted and binary only, and record that clearly.

# Phase 3 — Hard-pair report for true n-gram coherence

## Goal

Evaluate whether true filtered n-gram evidence improves hard-pair ranking.

## Script

```text
run_phaseB_filtered_ngram_hard_pair_report_v1.py
```

## Required score families

Build several transparent n-gram score families.

### N0 — Current scorer baseline

Use existing current-score preference for comparison.

### N1 — Normal 2-gram exact coherence

```text
normal cut
2-grams
log-weighted or unweighted hits
```

### N2 — Normal 3-gram exact coherence

```text
normal cut
3-grams
```

### N3 — Normal 4-gram exact coherence

```text
normal cut
4-grams
```

### N4 — Normal 2–4 combined

Balanced average of N1–N3, with caps so 2-grams do not dominate.

### N5 — Strict 2–4 combined

Same as N4 but strict only.

### N6 — Normal + strict precision support

Normal combined coherence plus a smaller strict support term.

### N7 — Longest phrase / highest-order hit

Rewards candidates with 3/4/5-gram hits, not just many 2-gram hits.

### N8 — Coverage score

Uses non-overlapping hit coverage over the 500-token candidate chunk.

### N9 — Repetition-aware n-gram coherence

Positive n-gram hit evidence minus repeated-fragment penalty.

### N10 — Span-Hamming support plus n-gram coherence

Combine fixed report-only span-Hamming support with true n-gram coherence:

```text
normal length 7 HD2 exact_count_norm support
+ filtered n-gram coherence
```

### N11 — S5 span-Hamming plus n-gram coherence

Use the previous S5 support signal plus n-gram coherence.

### N12 — Current-margin support policy

Use n-gram coherence only when current-score margin is small.

### N13 — Conservative support policy

Only override or flag when n-gram + span support margin is above a high threshold.

## Pairwise evaluation

For each score family, compute:

```text

truth_better_preference_rate
95% CI

breaks
net_rescues

```

```text

```

## Margin sweep

For each score family:

```text

applied_count
rescues
breaks

```

Suggested thresholds:

```text
0.0, 0.01, 0.025, 0.05, 0.10, 0.20, 0.30, 0.40, 0.50, 0.75, 1.00, 1.50, 2.00
```

## Correlation report

```text

```

This tells us whether true n-gram evidence adds independent shape or only repeats the existing scorer.

# Implementation notes

## Efficient index structure

For exact no-WLI scanning, use an index keyed by first token and length, or similar:

```text
encoded_token_length
first_token
token_tuple
metadata list
```

For each candidate chunk:

```text
for start offset:
  for candidate phrase length:
    check token slice in index
```

Avoid brute-force comparing every phrase to every offset.

## Duplicate encoded phrases

Different word n-grams may encode to the same token sequence. Preserve metadata:

```text
encoded_sequence
list of phrase_text variants
max frequency
sum frequency
dictionary_cut
ngram_order
```

Feature extraction should count encoded hits consistently and record whether phrase multiplicity is used.

## Frequency weighting

Use log weighting first:

```text
log_weight = log1p(raw_count)
```

Also compute unweighted features.

Do not let ultra-common 2-grams dominate. Use caps or per-order normalisation.

## Per-order normalisation

Each n-gram order should have its own normalisation before combined scoring.

Example:

```text
score_2gram_norm
score_3gram_norm
score_4gram_norm
```

Then combine:

```text
combined = mean(capped order scores)
```

Do not simply sum all hits across orders.

## FWD/REV separation

Even though assets include FWD and REV, this v1 hard-pair report should use FWD only unless the candidate corpus is explicitly REV.

If REV is tested later, it must have its own report and calibration surface.
