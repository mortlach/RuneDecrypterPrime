## 0) Hard Constraints (Non-Negotiable)

C0 - API stability (solver/runtime)
- No change to the token-based scoring call surface.
- Primary interface remains:
  - `score(plaintext: Iterable[int], wli_windows=None)`
  - `batch_score(pts, wlis=None)`
- Runtime fallback behavior remains intact.

C1 - No math change
- No change to objective math, weights, or normalization behavior in this phase.

C2 - `core/types.py` is the semantic source of truth
- Objective meaning must use existing `ObjectiveSpec` and enums from `core/types.py`.
- No duplicate objective enums or parallel semantic model.

C3 - Reporting is sidecar
- Structured `ScorerReport` is additive.
- Solver loops continue consuming numeric scoring outputs.

C4 - Tests are the gate
- No step is accepted without passing parity and safety tests defined in this plan.

## 1) Target Architecture (Minimal Additions, No Bloat)

### 1.1 Add `ScorerReport` (bounded, JSON-safe)

New file
- `src/rune_decrypter_prime/scoring/scorer_report.py`

Purpose
- Stable, JSON-safe record of what score was computed, what it means, and what it cost.
- Aligned with reproducibility and telemetry expectations.

Design rules
- Objective meaning stored as `ObjectiveSpec` from `core/types.py`.
- JSON-safe and bounded by default.
- No solver loop dependency.

Data shape (contract-level, not implementation dump)
- `objective_str: str`
- `objective_spec: ObjectiveSpec`
- `score: float`
- `raw_score: float | None`
- `telemetry: dict[str, Any]` (bounded)
- `metrics: dict[str, float]` (small derived numeric stats)
- `cost_ms: float | None`
- `details: dict[str, Any]` (bounded, top-N only)
- `to_json_dict() -> dict[str, Any]` (primitives only)

### 1.2 Add one report builder (anti-copy-paste enforcement point)

New file
- `src/rune_decrypter_prime/scoring/scorer_report_builder.py`

Purpose
- Single normalization point from scorer runtime outputs into `ScorerReport`.
- Prevents per-scorer and per-harness schema drift.

Builder inputs
- `scorer` (BaseScorer-compatible)
- `objective_str: str`
- `score: float`
- `raw_score: float | None`
- `cost_ms: float | None`
- `extra_metrics: Mapping[str, float] | None`
- `extra_details: Mapping[str, Any] | None`

Builder responsibilities
- Normalize objective string using existing helpers in `base_scorer.py`.
- Derive `ObjectiveSpec` using `core/types.py` enums.
- Pull and normalize `scorer.telemetry()` and `scorer.last_stats()`.
- Enforce bounded payload conventions.
- Never throw in a way that breaks scoring execution.

## 2) Fix Scoring Config Serialization (Reproducible Artifacts)

Problem
- `ScoringConfig.asdict()` currently risks leaking non-JSON primitives (notably `ObjectiveSpec`).

Touch
- `src/rune_decrypter_prime/core/config/scoring.py`

Goal
- `asdict()` emits JSON primitives only:
  - Enum -> `.value`
  - `Path` -> `str(path)`
  - `ObjectiveSpec` -> object with primitive fields (`family`, `stat`, `win`)

Compatibility decision (locked for this plan)
- Use Option 1.
- Keep `ScoringConfig.asdict()` JSON-safe for artifacts.
- Update `RuneScorer`, `RuneScorerTorch`, and `UnifiedRuneScorer` objective intake to accept
  `ObjectiveSpec | dict | str` and normalize internally.
- This preserves existing runtime/tutorial dict flows while making artifact serialization safe.

Boundary rule
- Do not invent a second objective model. Serialize the existing `ObjectiveSpec`.
