RDP Draft Plan: Move Data Out of src into assets (with build/preflight integration)
Date: 2026-03-06 (America/Los_Angeles)
Status: Draft for review

Goal
- Move large runtime data out of `src/rune_decrypter_prime/data/...` into `assets/...`.
- Keep code in `src/...`.
- Preserve deterministic setup/preflight and split-asset rebuild behavior.
- Keep benchmark and tests working during transition.

Non-negotiable constraints
- No guessing: all path/contracts driven by explicit manifests and tests.
- No privacy leaks: repo-relative paths in logs/outputs; no absolute machine paths persisted.
- No new CLI knobs for repo helper scripts; use hardcoded config constants where needed.
- Determinism first: hash/size checks and reproducible rebuild path.

Current baseline (important)
- Repo already has:
  - `assets_manifest_v1.json`
  - `assets_packed/`
  - `tools/benchmarks/community/setup_and_preflight.py`
- Preflight already supports:
  - recombine required assets
  - rebuild missing joint `.bin.zst` from split `*_part*.npz`
  - forward-link bridge between assets and src data path
- Current bridge direction in manifest notes points assets -> src target.

Target end-state
- Runtime large data root is `assets/` only.
- `src/rune_decrypter_prime/data/` retains code modules and tiny test/tutorial fixtures only.
- Language model and heavy tables live under:
  - `assets/language_model/lmp/...`
  - `assets/span_hamming/...` (or benchmark-scoring equivalent agreed path)
- Loaders resolve via a single in-code data root resolver.
- Setup/preflight validates and materializes assets under `assets/`, not `src/...`.

Name rationalization policy (add during migration)
--------------------------------------------------------------------------------
Objective
- Standardize names while moving assets so we do not carry legacy ambiguity.

Rules
- Use lowercase snake_case for files and directories.
- Keep direction and modality tokens canonical and ordered:
  - `<direction>_<se_mode>_<model>_n<n>_<stat>`
  - example: `ltr_nose_char_n4_logp`
- Prefer semantic folder grouping over historical script grouping:
  - `assets/language_model/lmp/{char,wli,ecdf}/...`
  - `assets/span_hamming/{calibration,ecdf}/...`
- Avoid version suffixes in every filename; keep version at folder boundary where possible.
- Keep one compatibility map for renamed paths during transition.

Required migration artefacts
- `naming_map_v1.json`:
  - old_relpath -> new_relpath
  - reason code (`normalize_case`, `token_order`, `grouping`, `legacy_cleanup`)
- one validator test to ensure no mixed naming patterns re-enter the tree.

Acceptance
- New assets follow canonical naming only.
- Legacy names resolve only through compatibility map during transition window.
