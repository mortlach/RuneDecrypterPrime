# 3. Target architecture

Keep it simple and function-based.

## A. Shared rescue engine

Create one small shared rescue layer that both replay and live call.

Suggested module split:

* `phasec_rescue_candidates.py`

  * build rescue-eligible starts
  * enforce challenger/anchor rules
  * apply rank-aware budgeting
* `phasec_rescue_mini_search.py`

  * slice-local mini-search
  * deterministic beam
  * keep-all-rows option
* `phasec_rescue_selector.py`

  * selector modes
  * baseline
  * top-score-then-search
  * rescue-shallow-then-search
  * future selector experiments
* `phasec_rescue_polish.py`

  * rescue-specific post-landing local polish
  * ordinary polish vs rescue-only deeper polish
* `phasec_rescue_checkpoint.py`

  * write compact per-start checkpoint rows
  * readable even if full run dies

These should be plain functions, not a class-heavy design.

## B. Thin live wiring

`stage3_two_phase.py` should stop owning all rescue details directly.

It should mostly:

* build Phase-C starts
* call the shared rescue engine for challenger starts
* call ordinary polish for anchor / plain challengers
* collect diagnostics
* choose final best

## C. Thin replay wiring

`replay_phasec_rescue_sweep.py` should stop having bespoke copies of rescue logic.

It should:

* load saved starts
* call the same shared rescue engine
* vary selector mode / guard threshold / replay-only truth scoring
* compare results

## D. Checkpointable diagnostics

Every Phase-C start should emit a small record with:

* start index
* source
* source rank
* lane
* rescue eligible / attempted / applied
* selector mode
* landing type
* init match / final match
* init score / final score
* anchor overtake flag
* rescue polish steps used

This must go to a durable file during the run, not only into the final instance.
