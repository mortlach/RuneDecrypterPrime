# Canonical cut-over criteria

This file defines the minimum bar for calling the migrated planning bundle
"canonical enough" for everyday use.

## A. Global criteria

### A1. Each active home has a stable live pack
At minimum:
- current state
- workstream index
- document map
- active runbook
- remaining-work file
- code/crosscheck note

### A2. Support/reference layers are clearly secondary
The active homes must say plainly:
- what is live support
- what is historical but useful
- what may move to archive later

### A3. Cross-project control layer is readable
At minimum:
- project index
- master timeline
- co-ordination board
- dependency map
- problem-thread index
- remaining-work file
- crosscheck status file

### A4. Legacy/archive no longer compete with live entry points
Older packs may remain, but the live homes should clearly outrank them.

## B. What does not have to be finished first

Not required before cut-over:
- bulk-moving every old file
- copying the entire live no-WLI tree into this bundle
- resolving every final architecture question
- writing every possible result/history note

## C. Practical cut-over test

The bundle is probably ready to act as canonical day-to-day planning when:
1. a new agent can start from the control layer without needing the old tree first
2. the three active homes read coherently as present truth
3. the remaining-work files make the unfinished parts explicit
4. the archive/legacy layers no longer feel like competing entry points
